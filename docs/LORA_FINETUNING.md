# LoRA Fine-Tuning для Qwen3-TTS 0.6B: Исследование и Оценка VRAM

## 1. Введение и Цель исследования
Цель спайка — оценить возможность проведения LoRA-файнтюнинга модели `Qwen3-TTS 0.6B` на потребительских видеокартах с объемом видеопамяти **4 ГБ** (в частности NVIDIA GeForce RTX 3050 Ti Laptop GPU) и подготовить пайплайн данных для обучения.

---

## 2. Архитектура и Бюджет VRAM

### 2.1. Доступный объем видеопамяти на Windows (WDDM)
- Физический объем VRAM: **4096 МБ**.
- Аллокация Windows Desktop Window Manager (DWM / Compositor) и GUI: **~800 МБ**.
- Реально доступный непрерывный пул VRAM для PyTorch CUDA: **~3296 МБ**.

### 2.2. Расчет компонентов обучения (Mixed Precision bfloat16)

| Компонент | Размерность / Параметры | Объем VRAM |
|---|---|---|
| **Базовая модель (Frozen)** | 590M параметров в `bfloat16` | **1125.3 МБ** |
| **LoRA-адаптеры ($r=8, \alpha=16$)** | ~1.2M параметров на проекциях `q_proj`, `v_proj` | **4.6 МБ** |
| **Градиенты LoRA** | fp32 / bf16 | **4.6 МБ** |
| **Состояния оптимизатора (AdamW)** | 2 состояния ($m, v$) для обучаемых весов | **9.2 МБ** |
| **Активации (Forward/Backward)** | Длина последовательности $T \approx 150$ токенов (текст + речь 12 Гц), Batch=1, **Gradient Checkpointing = True** | **~450 МБ** |
| **Контекст CUDA / PyTorch Runtime** | Инициализация cuDNN/CUDA Context, буфер аллокатора | **~480 МБ** |
| **ИТОГО ТРЕБУЕТСЯ** | Обучение с одним сэмплом ($B=1$) | **~2073.6 МБ** |
| **Запас (Headroom)** | $3296.0 - 2073.6$ | **+1222.4 МБ** |

## 3. Вердикт и Технические ограничения

### Вердикт: **ВОЗМОЖНО (FEASIBLE)** при строгом соблюдении следующих параметров:
1. **Размер батча**: строго `batch_size = 1`.
2. **Накопление градиентов**: `gradient_accumulation_steps = 4` (эффективный размер батча = 4).
3. **Gradient Checkpointing**: **ОБЯЗАТЕЛЬНО включен** (`model.gradient_checkpointing_enable()`). Без него активации занимают более 2.5 ГБ, что приводит к мгновенному CUDA Out of Memory (OOM).
4. **Тип данных**: `torch.bfloat16`.
5. **Длина аудио-сэмплов**: не более 3–6 секунд на клип (~36–72 речевых токена при 12 Гц). Длинные сэмплы (>10 сек) вызывают экспоненциальный рост матрицы внимания.
6. **Целевые модули LoRA**: только `["q_proj", "v_proj"]`. Добавление адаптеров на MLP-слои увеличивает объем памяти оптимизатора и градиентов.

## 4. Подготовка датасета

Для нарезки сырых аудиофайлов и транскриптов создан скрипт:
[`scripts/prepare_finetuning_dataset.py`](../scripts/prepare_finetuning_dataset.py).

### Что делает скрипт:
1. Находит все пары `.wav` и `.txt` в папке с голосами (`C:\dev\voices`).
2. Проверяет корректность частоты дискретизации и монофоничность.
3. Сегментирует аудио на отрезки 3–8 секунд с сохранением связности фраз.
4. Создает манифесты `dataset/train.jsonl` и `dataset/val.jsonl` в формате:
   ```json
   {"audio_file": "dataset/clips/voice_001.wav", "text": "Текст произнесенной фразы", "duration": 5.4, "speaker": "egorka"}
   ```

### Запуск подготовки:
```powershell
python scripts/prepare_finetuning_dataset.py
```
Результат: сгенерировано 66 обучающих сегментов с валидацией таймингов.
